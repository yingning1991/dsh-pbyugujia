# 技能沉淀的三件套：输入 / 输出 / 判据

> 2026-11-25 定。由来：一类活干完，下一次还能不能原样跑？能，才叫沉淀成技能。

## 为什么要有这条

agent 最常见的浪费，是同一类活每次重新摸索：上一次怎么做的写在对话里，压缩一次就没了；写进笔记也没用——笔记能被读，不能被执行。

技能沉淀要解决的不是「记下来」，是「下次能原样跑」。所以一件活做完，问一句：

> 这活下次能不能原样跑？

能 → 落成 `tools/*.mjs` 或 `tasks/*.md`，并在索引里加一行。
不能 → 记一条待办，写清「差什么、哪天收」。

## 三件套（缺一样就不算沉淀）

| 件 | 回答什么 | 反例 |
| --- | --- | --- |
| **输入** | 吃什么：路径、参数、前置状态 | 「跑一下那个脚本」——哪个脚本、给什么参数 |
| **输出** | 吐出什么：文件、ID、报告格式 | 「会生成结果」——生成到哪儿、长什么样 |
| **判据** | 怎么知道跑对了：能原样复跑验的 | 「应该没问题」——那是感觉，不是判据 |

判据这一条最容易漏。**没有判据的技能只是笔记。** 落进 `tools/` 的要能 `--check` / dry-run；落进 `tasks/` 的要写清验收命令。

## 写的时候顺手问三句

1. 下次第二次做这件活，第一步敲什么命令？（敲不出来 = 输入没写清）
2. 跑完我在哪儿能看见结果？（看不见 = 输出没落盘）
3. 错了怎么知道错了？（答不出 = 判据缺失）

## 回滚

这份文档只是判据，删掉不影响任何正在跑的流程；对应的落地物在各自的任务卡与脚本里。
