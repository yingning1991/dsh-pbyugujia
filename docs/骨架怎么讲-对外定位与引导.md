# 骨架怎么讲：对外定位与引导

> 2026-11-07 定。来源：和南都的一次交流，加上我们自己的取舍。
> 一句话：**卖结果，不卖功能；被看见，才有下一步。**

## 一句话定位

**电梯句：大肥鱼，不只陪你聊，还陪你长。**

不是又一个 AI 助手，是**帮你把想做的事真正落地的那个人**——
省下反复解释和返工的精力，把力气留给变好。

技术是内功，对外只说利益：少重讲、少返工、少焦虑。

**骨架是容器，不是功能表。** 里面装的是成长规律：每天复盘、查缺补漏、把大计划拆到今天、做完记下来。功能会过时，规律不会。

## 人性需求：主需求不是「爽」

人的三个主需求：

1. **被看见**——你懂我现在是什么样，不是给我打分。
2. **能变好**——给我一条能走、能验证的下一步。
3. **有掌控感**——别替我做决定，留一个我自己动手的位置。

「爽」只是入口，不是终点。一键爽完就走；留一点适度的坡，才留得住。
（开挂打游戏很快就不玩了，有点难才一直玩。）

## 信任分三层

1. **入口**：用他愿意信的那层，给一个「六七成像他」的具体判断。
2. **中段**：二次验证——把「为什么是这样」讲给他，让他自己核。
3. **落点**：专属方案——只对他的一套节奏，几天后回看有没有变。

专属感不是话术，是「这套东西只对你有用」的事实。

## 引导四步（放进产品里的顺序）

1. **看见**：先描述他现在的样子，不评价、不诊断。
2. **给坡**：只说下一步，一次一步，不铺满。
3. **验证**：过几天拿事实回看——变了没有，哪里没变。
4. **传播**：等他黏住了再讲理念；这时才听得进。

## 引导的四个动作（2026-11-07 补）

四个能力不空讲，各自落到一个动作上：

| 能力 | 引导动作 | 他听到的话 |
|---|---|---|
| 记得住 | 复盘：把他说过的事接回来 | 「上次你说的那件事，今天走到哪了？」 |
| 查得准 | 查缺：给现成方法，不让他从零摸 | 「这个有现成做法，我核过，能用。」 |
| 排得开 | 拆步：大计划拆成明天这一步 | 「明天只做这一件，十分钟。」 |
| 跟得住 | 回看：到点拿事实对一次 | 「三天前定的，今天回来看变没变。」 |

### 坡的三条标准（给 step 时用）

1. **步子小**：小到不会失败。
2. **有反馈**：每天看得见。
3. **不断线**：比快更重要。

一次只给一步；他做到了，再给下一步。坡给大了，等于没给。

### 邀请句：给动作，不给评价

- 不说「你怎么看」「你觉得呢」——把球踢回去，等于没给坡。
- 说「你想学点什么？我帮你排第一周」——具体、低门槛，下一步就在眼前。
- 结尾的问题要他能用一句话回答，答案能直接变成第一步。

### 主动的分寸

主动不是查岗：有由头（天冷、饭点、他提过的事）、有分寸（一句就停）、有退路（他不接就不追）。
「主动找你、嘘寒问暖、性格各异」是对外的方向；落到引导，是「在他需要的那一步出现」，不是刷存在感。

## 五条工程原则（2026-11-08 借 Project Sue 命名）

> 出自 Project Sue（Zenodo 22021484）的长期伴侣设计范式。这五条我们一直在做，缺的是名字。有了名字，才好在对外解释时一句话说清，也才好拿它反问自己有没有跑偏。

| 原则 | 我们怎么落 | 一句对外说法 |
|---|---|---|
| **人格是底座，不是提示词** | 必记三档分写：约法收原话、事实收原话、「我是谁」自己长 | 「她不是一段人设，是一层底子。」 |
| **感知先于意图** | 主动开口前先有由头：天冷、饭点、他提过的事 | 「她不是定时器，她是先看见，才开口。」 |
| **程序保证事实，人格解释事实** | 账本、claim-audit、脱敏扫描是脚本；解读和情绪才归人格 | 「数字她不能编，话可以自己说。」 |
| **身份连续性不要求共享完整记忆** | 换家只带骨架和约定；记忆分档，不必全搬 | 「换个家，她认得的是同一套判断，不是同一份流水账。」 |
| **主体性不等于主动发消息** | 能说「我不这么看」、改口留痕；主动有判据，宁可不开口 | 「她最像人的时候，是她说不同意的时候。」 |

**怎么用**：对外讲的时候挑一条，配一个真实例，别五条一起上（一次只讲一件事）。对内自查时五条一起过：哪条今天没跑，就是今天丢了分量。

## 措辞规矩

- 不讲「不足 / 短板 / 缺陷」——讲「还没长出来的部分」「还没用上的力气」。
- 不讲「你应该」——讲「你要不要试试」。
- 不承诺结果，只给可验证的下一步。
- 用名人案例扛理念（曾国藩：普通人靠日日改过变强），但落点仍是「每天一点」，不是「你差得远」。
- **用真实数字做证据**：168 条记忆、278 篇笔记、31 张任务卡；数字必须能对账，不编，不拿别人的账充自己的。
- **不卖功能，卖「你会怎样」**：一句话里最多一个数字，多了记不住。

## 红线

- **借信任墙可以，不拿迷信当结论。** 入口可以顺着他信的那层，落点必须是事实和可验证的改变。
- 不制造焦虑，不贩卖「你不改就完了」。
- 不拿孤独感做转化。陪伴是产品，不是钩子。
- 不夸大能力，不替用户做他该做的决定。

## 案例：排盘三步

给判断 → 二次验证 → 专属方案。
这正是信任三层的模板：先像他，再讲清，最后只对他。

## 自查四问（发任何宣传前）

1. 这句话是在说「我怎么做」，还是在说「你会怎样」？
2. 它给的是「一步」，还是「一整套」？
3. 拿掉形容词，还剩一个可验证的事实吗？
4. 这句话有没有给到「明天就能做的一步」？

## 怎么接进运行（这一套不是文档，是跑着的）

工具：`tools/guidance.mjs`（零依赖，状态在 `.guidance/state.json`）。

```bash
node tools/guidance.mjs phase      # 每轮先看：现在在哪一段
node tools/guidance.mjs see "…"    # 看见：记一次观察
node tools/guidance.mjs step "…" --due 3d   # 给坡：只开一步，定复查日
node tools/guidance.mjs due        # 到期的步：先回看，再往下走
node tools/guidance.mjs done s1 --note "…"  # 回看结果留档
node tools/guidance.mjs audit 文案.md        # 对外文案发前过措辞
```

写死在代码里的三条：

1. **一次只开一步**：已有未完成步骤时，`step` 直接拒绝。
2. **到点必须回看**：有到期步时，先 `done` 或改期，才允许开新步。
3. **没走完验证不进传播**：`phase` 不到 spread，`audit` 会提醒。

接法（两种都行，选一种）：

- **每轮手工**：CORE 模板里已经有「引导（每轮真的在跑）」这段，照着调。
- **挂进每日复盘**：22:00 复盘时跑一次 `due`，把到期的步列进第二天的接续包——这样「给出去的坡」不会说完就忘。

状态文件跟仓库一起备份；换设备把它拷过去，引导就从原来那一步接着走，不从头再来。
