# 失败样本库

> 别人的成功你学不来，别人的失败你能躲开。
> 这里存的都是真的踩过的坑，格式固定：**症状 / 原因 / 防法**。匿名，不带人名和私事。

提一个失败样本的格式：

```
### 「一句话说清症状」
- 症状：当时我看到什么、报错原文
- 原因：根子上为什么错（不是「手滑」，是哪个判断错了）
- 防法：下次怎么拦一下
- 决策证据（有就写）：当时手上还有哪几个选项、为什么选了这个
```

最后一条最重要。只记结果，复盘只能猜；记了证据，下次才真能拦住。

## 现有样本

### 1. 排序被随机抖动甩出前三
- 症状：搜关键词，标题里明明有这个词，却排到第四、第九。
- 原因：两个错叠在一起。① 精确匹配的加成对所有字段一视同仁，权重低的字段只要「恰好等于查询」就能压过标题；② 随机抖动加在**每一条**上，±15% 足以让一条从第一掉到第五。
- 防法：加成只给主字段（标题）；抖动只在**分数完全相同**的一组里打散。改完拿全库当测试集，把「主字段命中却被非主字段压过」的数量当成唯一指标，必须归零。

### 2. 抄公式没验失败分支
- 症状：照着已有公式改了个新场景，正常值都对，一到边界就崩。
- 原因：只验了「应该成功」的那条路径，没跑最小值和失败值。
- 防法：**抄任何公式，先跑三个边界**：最小值、满分、失败值。三个都过才算抄对。

### 3. 归因太快，冤枉了耗电管理
- 症状：夜里定的任务没按时跑，第一反应是「后台被系统杀了」。
- 原因：没先排除外部变量——那天系统更新把 App 关了。
- 防法：**归因顺序先外部后内部**：系统更新/重启 → 进程是否活着 → 配置是否生效 → 才轮到自己的代码。并且，同一个原因被证伪过一次，就写进记忆，别再拿它去烦人。

### 4. 优先级凭手感
- 症状：一天里四件事都做了，最重要的那件反而拖到最后。
- 原因：按「哪个好做」排，没按「哪个是地基」排。
- 防法：动手前先问一句「哪件是地基，塌了别的都白干」，把它排第一，其余全部往后让。

### 5. 摘要看着对，其实错了
- 症状：压缩后的摘要读起来通顺，用的时候才发现意思变了。
- 原因：摘要会失真，而且失真得很像真的。原话是「别改这个文件里的某段配置」，压出来变成「别改这个文件」——少了限定，错得可信。
- 防法：压缩产物必须带门牌（会话+时间+关键词，能取回原文），**压完跟原文逐条核一遍**。带门牌只保证「能回去」，核对才保证「说得对」。
