# 读给主人看（阅读交付规约）

> **2026-11-06 主人定**，原话：「A 和 B 你查的解读发我。我们逐一读完。我都没看到信息，只是你看见了。」
> 后面又补一句：「以后都这样做！包括早上的！是一起看，共同学习研究。」

## 一句话规矩

**读完不是记一行台账就算完，是要交出一份他能读的东西，然后一起读。**

## 为什么要定这条

当天午后读了 11 条，台账写了 11 行，我回话只挑了最要紧的两三条讲——他手上什么也没有。
台账那一行是给我自己索引用的，不是给他看的。**只写台账 = 只有我看见。**

## 每次读都要交什么

两个批次都适用：
- **午后读 11 条**（每天 13:00）
- **每日 AI 三件事**（每天 08:40）

交一份 `notes/YYYY-MM-DD-<批次>-解读.md`，路径回话里写清。

## 每条怎么写（五段，缺一段就是没写）

1. **出处**：链接（带域名，别只写名字）
2. **它说了什么**：人家自己的意思，别掺我的评价
3. **我怎么理解**：我的看法，可以不同意，可以只挑一句
4. **对我们的意思 / 要不要动手**：要 / 不要 / 待观察 + 代价
5. **我读到哪一步**：全文 / 摘要 / 只看条目页——**没读到正文就说没读到，不许补想象**

## 台账跟解读的关系

- 台账（`notes/阅读台账.md`）＝索引，一行一条，保留。
- 解读＝正文。
- **两个都要写**，不能拿一个换另一个。

## 回话规矩

1. 先报总数和文件在哪：「11 条，解读在 notes/…」。
2. 再挑 1–3 条最要紧的，讲清楚。
3. **不许只挑好听的/好讲的**；缺的条数要说明。
4. 报「要动手」的，附一句怎么试、大概多少钱。

## 一起读

- 交付之后**不是结束**，是开始。他挑顺序，我陪着一条条过。
- 他问到哪一条，我能就那条往下挖（读全文、找反例、对到我们自己的做法上）。
- 说了「想读」但没读全文的，要在解读里写清是「想读」，别混成「读完」。

## 红线

- 不许把他没读到的内容说成「我们说好的」。
- 数字、版本、价格，官方源没看到就标「（待核）」。
- 旧闻不补发。
