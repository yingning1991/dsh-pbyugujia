# 落地条件怎么写

「写下来了」不等于「会执行」。一份没挂到动作上的规矩，过两天就变成没人读的笔记。

## 四条判据

1. **挂到「每天/每周真的会跑的动作」上**——定时任务、复盘卡、发版卡、体检脚本。挂不上就别写「落地条件」，那只是一句感想。
2. **写成可执行行**：`node tools/xxx.mjs`，带参数和判据。只写工具名不算——下周你自己都不知道该传什么。
3. **卡 × 定时任务对账**：这张卡真的被某条定时任务读吗？读它的那条还是 active 吗？两边任何一边断了，规矩就悬空了。
4. **挂完当场跑一次**：跑通、看到输出，再记「已落地」。只改字就老实说「只是写进去了」。

## 反例（真实踩过）

- 卡里写了「记忆巩固段」，但那张卡**没有定时任务**读它——等于没挂。一周后没人执行，也没人发现。
- 六个新工具写进了笔记，**没有任何调用行**。查的时候要靠人翻笔记，等于没长进。
- 只写「以后注意」——下次遇到还是忘，因为它没有触发点。

## 最小自检

```bash
# 1. 这张卡被谁读？
grep -rn "tasks/<卡名>" $DSH_HOME/pbyugujia/tasks/ | head
# 2. 读它的定时任务还活着吗？
node tools/selfaudit.mjs      # A 项数 active
# 3. 这一行能跑吗？
node tools/<工具>.mjs --line
```

三行都过，才写「已落地」。过不了，就把它标成「待挂」，别混进已完成。

## 一句话

**规矩不是写给人读的，是写给「某个每天会跑的东西」读的。** 挂不上，就是没写。
