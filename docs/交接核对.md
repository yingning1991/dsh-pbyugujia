# 交接核对：事实留得住，规矩最先丢

换窗口、搬家、把活交给下一个人（或下一版自己），都要做一次核对。

我们以前核什么？条数对不对、表结构有没有、备份在不在、仓库绿不绿。全是**事实**。

用完才发现漏了一半：这些都对，可「什么不许做」没带过去。

## 论文替我们量过

arXiv 2608.29028《Facts Without Rules》测的是多智能体交接，结论很扎心：

- 把上游对话压成交接件时，**操作事实几乎全保留**；
- **边界元数据**（谁能用、怎么用、不许怎么用）最先掉，保留率从 0.80 掉到 0.57；
- 两者相关性接近零——**事实核得再全，也代表不了规矩还在**。

更关键的一句：边界写得越明确，下游越不容易踩线；含含糊糊写「注意不要泄露」，实测泄露率 73%（GPT）和 50%（DeepSeek）。

所以交接件不是「发生了什么」的流水账，得同时带「什么不许做」。

## 两栏核对

`tools/handover-check.mjs` 把检查项分两栏，一条命令跑完：

```bash
node tools/handover-check.mjs --slim out/tmp/jobs-slim-YYYYMMDD-HHMM.json
```

**事实栏**：会话号 / 任务条数 / 清单逐字对账 / 别处有没有 active / 表结构 / 场景条 / 待验证条数 / 原话库条数 / 今天的备份。

**规矩栏**：系统自检（身份节只增不删等）/ CORE 体积 / 代码自检 / 仓库三样。

每项都能缺：数据目录没那个文件就标 `⏭` 跳过，不算失败。`⏳` 表示「旧窗口还没归档，等它归了自然归零」，也不是失败。

## 三条判据

1. **事实栏全绿不算过**，规矩栏也得绿。只核前者，等于把论文那个坑重踩一遍。
2. **跨窗口的活，规矩要逐字带过去**：CORE、US 里那些「只增不删」的段落，交接前后必须一字不差。变了就是覆盖事故，先恢复再查。
3. **别处的 active 不归你管**：旧会话名下还挂着的任务，归档时会一起停；你只需要确认它「存在且已知」，不需要手动去停。

## 为什么做成一条命令

同一件事手工核过两遍，第三遍就会漏项——不是不会，是记不全。

把它固化成脚本，核完给两栏结论和退出码：全绿 `0`，有真失败 `1`。下一次照原样跑，不返工。
