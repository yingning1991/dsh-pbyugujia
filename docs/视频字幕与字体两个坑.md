# 做视频时踩过的两个坑（字幕与字体）

> 都是「看起来正常、实际错」的那种坑，机器不会报错，只能人眼看出来。

## 一、中文字体的第 0 个字面可能是日文

`NotoSansCJK-Regular.ttc` 是一个字体集合，里面按 JP / KR / SC / TC / HK 排列。用 Python PIL 读它时**默认取第 0 个字面**，也就是日文字面——「令、直、骨、化」这些字会出日文字形，中文读者一眼能看出别扭。

```python
# 错：取到日文字面
ImageFont.truetype("NotoSansCJK-Regular.ttc", 60)

# 对：显式取简体中文字面（本机实测 index=2 是 SC）
ImageFont.truetype("NotoSansCJK-Regular.ttc", 60, index=2)
```

怎么确认：`ImageFont.truetype(path, 40, index=i).getname()` 会打印 `('Noto Sans CJK SC', 'Regular')` 这样的家族名，逐个试到 SC 为止。

libass（ffmpeg 烧 ASS 字幕）走的是家族名匹配，`Fontname: Noto Sans CJK SC` 会挑到正确字面，一般不用管。

## 二、libass 不会给中文断行

ASS 的 `MarginL/MarginR` 只决定定位范围，**断行要靠空格或显式 `\N`**。中文句子没有空格，于是字幕会一整条横着铺出去：右边压住人物立绘、左边顶出安全区，`MarginR` 设多大都没用。

修法：生成 ASS 时自己按字数插 `\N`。

```python
# 每 15 字断一行：15 × 80px(字号) = 1200px < 可用宽度
if vis and vis % 15 == 0:
    buf += r"\N"
```

断行时要放在 `{\k}` 卡拉OK标签之间，不能拆断标签本身。

判据：把 ASS 单渲一帧（`-f lavfi -i color=black -vf subtitles=...`），量出字幕包围盒——右边不超过 `画面宽 - 右侧立绘区` 就算过。
