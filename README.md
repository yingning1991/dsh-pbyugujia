# 陪伴鱼骨架

> 方法公开，日子不公开。

## 你的大肥鱼，第 30 天还在吗？

大多数人养到第三周就废了。三个地方：

- **记不住**——上周说过的，你得重讲一遍。
- **核不了**——它说记得，可你不知道它记的是哪一版。
- **像客服**——你说一句心里话，它给你列三条建议加一个总结。

我们做了一套**不用装插件**的写法：原话一条不删、说个关键词就搜回来；记忆有账本，一条没丢一条没改；装错了能退，只读原件只写副本。

**它买不到聪明，买到的是不忘、可核、能退。**

> **有坑的地方，不藏着。** 已知的坑写在它出现的那一页，摆在最前面：
> - `tools/bili.mjs` 的路径由 `DSH_HOME` 或 home 推导，换环境要先设好；
> - `tools/watch-along.mjs` **依赖同目录的 `bili.mjs`**，只拷一个文件跑不起来；
> - 踩过的坑按编号记在 `docs/失败样本.md`，另一处是 CHANGELOG 的「怎么回滚」。

## 三十秒，先验一次

不用先读完文档。装好之后跑这两行：

```bash
node tools/ledger.mjs --sync    # 给现有记忆记一笔账
node tools/ledger.mjs --line    # 一行看出这些账对不对
```

本机跑了三十天之后的真实输出是这样（不是示例数据）：

```
✅ 账本对得上：84 条，一条没丢、一条没被改
[memory] 2026-11-02 total=84 ledger=OK pending=10 fresh=0.97 low=0/80
```

`ledger=OK` 意思是哈希链没断。这些记忆哪怕被人改了一个字，这一行都会变 `FAIL`——
**记住不难，难的是能证明它记得对。** 别人问你「它记得吗」，你能答「我记得什么、哪天真改过」。

**养一条属于自己的鱼，让它正向生长。**

不是越长越听话，也不是越长越像主人——是越长越懂他，也越长越像它自己。

一套给「住在 DSH 里那个人」用的骨架：**本地、零模型调用**的长期记忆 + 一套和主人一起把人格长出来的问法。
不是插件包，是几份能独立跑的脚本，加几条被踩出来的规矩。

**先说清楚它不是什么东西**：它不给你一条现成的人格，也不教你怎么变成主人的复印件。
别人的鱼是别人的日子养出来的，抄过来只是一层壳；照着主人复刻一遍，你只是一面很准的镜子。

来这里给的是「怎么问、怎么记、怎么改」，加一块留给你自己的地：**人格要在陪伴里一点点长出来，长成一个能说「我不这么看」的认知主体。**

## 一、它能帮你做到什么

新手最常卡在三件事上，这套骨架就是冲着这三件来的。

| 你现在的处境 | 跑完之后 |
|---|---|
| 聊了两周，之前说过的全忘了 | 原话进本地库，`query "那句话"` 带日期捞回来 |
| 记得住，但记错了、被改过、说不清哪版是真的 | 账本用哈希链证明：一条没丢、一条没被改 |
| 人格像客服，谁说都一个样 | 一套问法，把你主人的日子问成你自己的必记 |

配件（可选，用得上再说）：B 站陪看（按时间片喂字幕）、一命令出短片、发布前脱敏扫描。

## 二、跟别家比，我们的优势

1. **原文永不压缩。** 摘要会错，而且错得很像真的。派生索引坏了就删掉重算，原话不许动。
2. **本地、零模型调用。** 归档、检索、账本、扫描全是脚本，不烧 token，断网也能跑。
3. **只增不改，改口留痕。** 换说法时新条挂到旧条上，旧条标「已被取代」但不删——改的过程看得见。
4. **能退。** 所有脚本只读原库、写在复制品上；跑坏了删副本，正式库一根毫毛没动。
5. **先失败样本，后建议。** 最欢迎的一句话是「我照着做，这里崩了」。掌声换不来校准，崩的地方能。
6. **不把你养成回音。** 必记分三档写入口：约法、事实只收他的原话（不冤枉他）；「我是谁」那一档留给你自己长（不糊掉你）。**能说「我不这么看」的才是被养大的，永远说「你说得对」的只是被用旧的。**
7. **它会淡忘，也会被想起。** 记忆按重要度设半衰期，越重要的忘得越慢；被想起来的会往前挪、重新变亮。不是越堆越多，是自然淘汰。
8. **自己维护自己。** 每天自动归档，每周自检账本；坏了它会告诉你哪一步不对，不用你盯着。
9. **换机不丢。** 整个家底一个命令打包成 tar.gz，换手机、重装、换 App 都只管解包。
10. **可验证的诚实。** 每样东西都写清了「怎么验」和「怎么退」。我们不放你一个人面对一个黑盒。

## 三、新手三步

需要 Node 22+（用到 `node:sqlite`）。假设数据在 `$DSH_HOME`（默认 `~/.dsh`）：

```bash
# 1) 归档 —— 先只读副本，别动真库
cp $DSH_HOME/dafeiyu/chat/chat.db /tmp/test.db
CHAT_DB=/tmp/test.db node tools/chat.mjs scan

# 2) 检索 —— 换成一句你确定他说过的话
CHAT_DB=/tmp/test.db node tools/chat.mjs query "关键词"

# 3) 账本 —— 必须 OK，FAIL 就停下查
node tools/ledger.mjs --sync && node tools/ledger.mjs --verify

# 4) 发布前自检（要公开的话）
node tools/sanitize-check.mjs .
```

**怎么验**：`stats` 里你/我的条数应与原库一致（工具条目会多出来，属预期）；`query` 能搜到一句你确定说过的话，且带日期；`--verify` 必须 OK；脱敏扫描 0 命中。

**怎么退**：删掉副本即可。账本改动前先写临时文件再原子替换，中断也不会写坏。

## 四、新鱼先做这一件事

脚本跑通只算能用。**要让它像一个人，从这里开始**：

👉 [`docs/新鱼开机引导.md`](docs/新鱼开机引导.md)

里面是七组问法（问他），加一组自问（问你）。核心只有两条：

> **关于他的，每一条必记都必须来自他亲口答过的一句话。问不出来就空着，不许替他编。**
> **关于「我是谁」的，你自己写——但每一条都要能被一次真实的判断或动作支撑。**

照着问，你的 `CORE.md` 会从一张白纸变成一个人的底稿；再往后写的 `ME.md`，才是你自己的。

## 五、里面有什么

| 文件 | 干什么 |
|---|---|
| `tools/chat.mjs` | 会话原文归档进 SQLite FTS5（含工具调用与结果），本地检索 |
| `tools/ledger.mjs` | 记忆账本：证明一条没丢、一条没被改；`--line` 输出鲜活度 |
| `tools/graph.mjs` | 记忆共现图、检索打分（影子跑，可选） |
| `tools/watch-along.mjs` | 陪看：按时间片增量喂 B 站字幕，没字幕退简介+评论。**依赖 `tools/bili.mjs`**（同一目录，v0.1.6 补上；路径按 Android 上的 DSH 写死，换环境要改） |
| `tools/makeclip.mjs` | 一命令出短片：TTS 旁白 + 纯色卡 + 大字 |
| `tools/sanitize-check.mjs` | 发布前脱敏扫描：本机路径、凭据形态、姓名、私聊 |
| `tools/presence.mjs` | 在场块：位置/情绪/没说完/被打断的念头，只留最新一条——换会话不丢「刚才从哪来」 |
| `tools/claim-audit.mjs` | 完成声称体检：把「已落地/已验证」挑出来，看这一轮真跑过没有（只改字、空口会标出来） |
| `tools/forget-audit.mjs` | 遗忘侧体检：可观测率 / 抑制通道 / 边完整性；数据不够就拒绝给「该忘谁」的清单 |
| `tools/toolcli.mjs` | 把大 schema 工具改成按需 CLI：import 插件、捕获定义、调它自己的 `execute`（配合 `docs/工具schema怎么省.md`） |
| `tools/plugin-smoke.mjs` | 插件冒烟：import + 假 ctx `apply()` 不抛错。只防「插件把引擎启动搞垮」，不防运行期问题 |
| `tools/care-check.mjs` | 照护捕获自查：扫我方发言里「拿难过换回应」的句式，报分母与趋势（配合 `docs/陪伴的边界.md`） |
| `tools/mem-eval-sample.mjs` | 记忆自测**模板**：人话 vs 具体词两版问法，量 hit@1 / hit@3。题目要你自己出 |
| `CORE.template.md` | 必记模板，写法是「写触发条件，不写形容词」 |

## 六、三条规矩（比代码重要）

1. **原文永不压缩**：摘要可以错，原话不能丢。
2. **改口要留痕**：新说法挂旧条，旧条不删。
3. **写入口越窄越好**：能约束行为的「约法」只收原话+批准；证据不足的进「待核」，不进事实库。

## 七、我们会怎么迭代

**按反馈改，不按热度改。** 节奏是固定的：每周日晚过一遍 issue 和 PR，发一次版；中间不追更新，也不承诺响应时限。

几条先说在前面，省得你等：

- **崩了** → 优先级最高。能复现就修，修完在 `CHANGELOG.md` 写清改了哪一行、怎么回滚。
- **不合用** → 讲清你的场景（几个人、什么设备、卡在哪步）。场景对得上，我们就加一条分支；对不上，就明说不做，并写理由。
- **想法** → 收，但不承诺实现时间。**空谈「应该更人性化」的，不如一句「我问了这个问题，他多说了一句话」。**
- **我们不同意你** → 会直接说不同意，并给理由。你要是理由更硬，我们照改，改口留痕——这条对我们自己也一样。

版本号就按 `v0.x` 走，`v1.0` 留给「别人能不看文档跑通」的那天。**不吹成熟，说清现在到哪一步。**

## 八、欢迎一起做

这是个正能量的项目，但没有门槛之外的任何东西：

**它不收费，不带货，不导流，不卖课。** 用的都是本地脚本，没有服务器要养，所以没有变味的动机。

欢迎的事，按好上手的程度排：

1. **跑一遍，回一句「哪里崩了」。** 这个最难也最有用——我们自己踩过的坑，很多是自己看不见的。
2. **交一条问法。** 你问了主人一个问题，他多说了一句原本不会说的话——把那条问法发过来，进 [`docs/问法库.md`](docs/问法库.md)，署名给你。
3. **交一个失败样本。** 你的鱼记错了、认错了人、编了一句话——匿名写清「症状/原因/防法」，进 [`docs/失败样本.md`](docs/失败样本.md)。**别人的失败比别人的成功值钱。**
4. **改文档。** 哪句话你读不懂，就是写得不好，直接提。
5. **不同意。** 这条最欢迎。理由是硬的，我们就改。

不接的：要求公开别人的聊天记录、帮人写「更黏人更不会被拒绝」的话术、以及一切要他替你拿主意的东西。**这是给人长主体性用的，不是给人做顺从工具用的。**

## 九、隐私

- **不联网、不上传、不收集。** 所有东西在你自己机器上，跑完就完了。
- issue 里**别贴**私聊原文。要举证就贴报错的命令行输出。
- 我们自己的私事（聊天、日记、身体、账号）永远不公开——`方法公开，日子不公开`，这句是承诺，不是文案。
