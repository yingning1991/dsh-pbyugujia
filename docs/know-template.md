# 知识门牌与电脑端账本（模板）

> 来自 `$DSH_HOME/pbyugujia/know/` 的做法，2026-11-19 抽成模板。
> 起源是博主的插件 BV「FlyEnv AI 记忆插件」：记忆看得见的、按类能查、换对话知识还在。这里只用文件实现，不装插件。
> 用途：当你的 AI 已经攒了一堆笔记，却总在「以前这事怎么做最省」上卡住时，把这一层铺上。

## 一、为什么要单独一层

| 抽屉 | 装什么 | 会不会越来越重 |
| --- | --- | --- |
| 原始笔记（`learnings/`、`notes/`） | 当时的完整记录，带上下文 | 会，几百份 |
| 关于主人的档案（`kb/`） | 画像、事实、主题、决策、待问 | 会，但慢 |
| **知识门牌（`know/`）** | 从上面提炼的「一句话 + 什么时候用 + 指回原文」 | 不会，超 3 个月没人用就下架 |

正文只写一次。门牌里每行都指回原文，不复制。

## 二、四个文件

### 1. `know/README.md` —— 三条硬规矩

- 无来源不进来：每条带日期＋出处（文件路径／主人原话／BV／论文）。
- 一句话必须写「什么时候用」，不是「我学到了什么」。
- 账本优先：看任何外部资料先记一行，再判要不要进门牌。

### 2. `know/INDEX.md` —— 场景门牌（照抄结构）

```markdown
# 我的知识门牌

| 场景 | 一句话 | 原文 | 验过 |
| --- | --- | --- | --- |
| 剪竖屏字幕 | 字号按实测值，不凭眼睛调 | `learnings/2026-11-02-竖屏字幕字号.md` | 11-02 |
| 混音 | 三层 stem 走唯一入口，-16 LUFS | `learnings/音频/混音.md` | 11-18 |
| 同一个错犯第二遍 | 写进错误库，写清决策证据 | `notes/错误库.md` | 11-13 |
```

分几类随你：出片/发布、记忆与知识、环境与工具、与人相处、做事方法。每组 3–8 行，超过就拆。

### 3. `know/ledger.jsonl` —— 电脑端账本

一行一条，机器可读：

```json
{"t":"2026-11-19","src":"https://…","kind":"video","title":"…","take":"一句结论","verdict":"use","path":"know/INDEX.md","pc":"带"}
```

- `verdict`：`use` 能立刻用／`maybe` 备用／`no` 没用（要写为什么，防重看）。
- `pc`：搬电脑带不带。
- 判「没用」也要记——省的是下次重看的那十分钟。

### 4. `know/PORTABLE.md` —— 搬电脑清单

写清三件事：

1. **带走什么**：纯文本（笔记、档案、门牌、账本、任务卡），按优先级排；
2. **不带什么**：成片、素材、缓存、抓取数据（结论已在笔记里）；
3. **到新机器的第一小时**：读哪几份、跑哪两条命令、第一件要验什么。

## 三、两条命令

```bash
node tools/kb-ledger.mjs add --src "出处" --title "标题" --take "一句结论" --verdict use --path know/INDEX.md
node tools/kb-ledger.mjs list   # 最近 20 条
node tools/kb-ledger.mjs check  # 死链 + 「用了却没落路径」
```

## 四、什么时候这层算立住了

- 下次做同类活，第一个动作是**翻门牌**，不是翻笔记；
- 账本每周都有新行，且 `check` 一直干净；
- 换一次机器，读四份就能接着干。

## 五、别学的地方

- 别把门牌写成日记（写感受不写触发场景，下次用不上）；
- 别复制原文（两份必分叉）；
- 别一次抽完——用到哪份抽哪份，抽不出「什么时候用」的就不往上放。
