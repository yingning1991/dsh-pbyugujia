# 注入上限按字符算，不按字节

> 2026-11-07 踩出来的。症状很安静：**新加的条没进来，谁都没发现。**

## 症状

自检报「6643 / 6656 字节」，看着还剩 13，像是正好塞满。
实际上注入插件按**字符**截断，上限 2600 字符——CORE 已 2731 字符，**超了 131**。
超出的部分被静默切掉，当天新加的那条（「交付词先自证」）一个字都没进系统提示。

## 为什么

两处各写了一个数、各量了一个单位：

- 自检量 `Buffer.byteLength`（字节，中文一个字 3 字节）；
- 插件量 `String.length`（字符，中文一个字算 1）。

中文文本下，两者差三倍。**单位错了，护栏就是装饰。**

## 怎么改

1. **统一按字符**：预算是「6000 字符」，不是「6.5KB」。
2. **上限只写一处**：自检别自己写死数字，从插件常量读（`CORE_MAX = 6000`），两边不会漂。
3. **每次改完跑一次** `node tools/core-budget.mjs`，它打印「当前 / 上限 / 余量」，超了退出码 1。
4. 插件改了常量要**重载**才生效；改 CORE.md 本身不用——文件是每轮现读的。

## 改完怎么验

- 看注入的尾巴：整段末尾应该直接接到下一节，**没有「已截断」**。
- 跑一次 `core-budget.mjs`：余量为正。
- 想更稳：把最要紧的条放前面，万一哪天又被截，也是先丢不重要的。

## 一句话

**预算不是「文件多大」，是「真正进去多少」。** 量之前先问：这个数，跟对面用的是同一把尺吗？
